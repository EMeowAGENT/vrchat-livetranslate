本模块是纯配置型 leaf，由三类 GitHub 资源组成：
- `workflows/ci.yml`：主入口，在 `push main` / `pull_request` / `workflow_dispatch` 触发，按平台拆 job——Windows (`tests` + `package`) 跑语法检查、ruff(F,E9)、凭据扫描、离线测试与 PyInstaller 打包；Linux (`linux-tests` + `appimage`) 用 xvfb 跑 Tk 用例并复用 `appimage.yml`。
- `workflows/appimage.yml`：被 `ci.yml` 与 `release.yml` 通过 `uses: ./.github/workflows/appimage.yml` 调用的可复用 workflow（`on.workflow_call`），集中维护 Linux AppImage 的系统依赖、uv+Tcl/Tk 缓存 key、`scripts/build_appimage.sh` 构建与 `scripts/verify_appimage.py` 独立验收的单一口径。
- `workflows/release.yml`：仅在 `v*` tag 或手动触发时运行，先调用 appimage.yml 产出 AppImage artifact，再在 Windows runner 上打 exe、校验大小与 SHA256SUMS.txt，最后用 `softprops/action-gh-release` 把两个附件挂到 Release。
- `ISSUE_TEMPLATE/bug_report.yml`、`feature_request.yml`、`config.yml`：GitHub Issues 表单模板。
- `pull_request_template.md`：PR 描述模板，强制填写改动类型、影响平台、验证证据、真机结论、文档/词表同步状态及本地测试清单。
依赖方向单向向外：仅读取仓库代码、调用 `scripts/*` 与 `requirements-*.txt`，不反向依赖业务代码。
